# 4.1.8 가이드–구현 매핑

| 가이드 내용 | 구현 위치 | 검증 |
|---|---|---|
| 동기 REST 호출 | `EligibilityClient`, `EligibilityController` | 정상 신청 테스트 |
| Context 전달 | `RequestContextFilter`, `ServiceRequestContext`, `EligibilityClient` | 세 헤더 전달·ID 생성·요청 격리 테스트 |
| connectTimeout/readTimeout | `EligibilityClientProperties`, `RestClientConfiguration` | 프로필 로딩과 read timeout 테스트 |
| 애플리케이션 timeout·하위 오류 처리 | `EligibilityClient`, `GlobalExceptionHandler` | 전송 실패와 모든 하위 5xx의 일반화된 503, 예상하지 않은 하위 4xx의 502 및 내부 정보 미노출 테스트 |
| VirtualService timeout | `deploy/istio/eligibility-timeout-virtual-service.yaml` | `timeout: 2s` 정적 검증 |
| 정상·지연·오류 검증 | `DemoOnlyBehaviorStore`, Postman | ELIGIBLE, INELIGIBLE, DELAY, ERROR |

## 정상 호출

```mermaid
sequenceDiagram
  participant U as Client
  participant F as RequestContextFilter
  participant A as ApplicationService
  participant C as EligibilityClient
  participant E as EligibilityController
  U->>F: POST /api/applications + Context
  F->>A: ServiceRequestContext
  A->>C: checkEligibility
  C->>E: GET /internal/eligibilities/{id} + 3 headers
  E-->>C: EligibilityResult
  C-->>A: eligible=true
  A-->>U: 저장 후 201 ACCEPTED
```

## 타임아웃 적용 위치

```mermaid
sequenceDiagram
  participant A as ApplicationService
  participant C as RestClient
  participant M as Mesh data plane (optional)
  participant E as EligibilityService
  A->>C: 동기 호출
  Note over C: connect/read timeout
  C->>M: HTTP request
  Note over M: VirtualService 전체 요청 timeout 2s
  M->>E: 내부 GET
  alt 앱 timeout 또는 통신 실패
    C-->>A: 일반화된 503
  else Mesh timeout
    M-->>C: 504
    C-->>A: 일반화된 503
  end
```

Mesh 정책은 timeout 응답을 생성하고, 이를 외부 업무 오류로 변환하며 내부 정보를 숨기는 책임은 application-service에 있다.

## 하위 HTTP 응답 변환

`EligibilityClient`는 HTTP 상태별 프록시 세부 정보를 외부 계약으로 노출하지 않는다. 하위 서비스의 모든 5xx(500, 502, 503과 Mesh가 반환할 수 있는 504 포함)는 `503 ELIGIBILITY_SERVICE_UNAVAILABLE`로 일반화한다. 예상하지 않은 하위 4xx는 `502 DOWNSTREAM_RESPONSE_INVALID`로 변환한다. `eligible=false`는 전송 장애와 구분하여 기존처럼 `422 ELIGIBILITY_DENIED`로 처리한다. 오류 응답에는 내부 URL, 하위 응답 본문, 예외 클래스와 stack trace를 포함하지 않는다.
